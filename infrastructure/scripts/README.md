A few decisions worth explaining:
bootstrap.sh is intentionally outside Terraform. The S3 bucket and DynamoDB table are Terraform's own prerequisites — you cannot use Terraform to create the backend that Terraform needs to initialise. The script is fully idempotent: every resource creation is preceded by a describe/head call, so re-running it after a partial failure is safe.
us-east-1 gets special-cased in bootstrap.sh. AWS S3's create-bucket API treats us-east-1 as the implicit default region and rejects requests that include a LocationConstraint for it. Every other region requires one. This is a long-standing AWS API quirk that silently breaks bucket creation when scripted naively.
The bucket gets five security settings applied. Public access block and HTTPS-only bucket policy are the minimum security baseline. Versioning enables state file recovery. AES-256 encryption at rest. A lifecycle rule to expire non-current versions after 90 days — without this, every terraform apply appends a new S3 version to the state file indefinitely, which becomes a meaningful storage cost over months.
deploy.sh forces SKIP_TESTS=false for prod regardless of the flag. The flag is accepted without error so the caller isn't confused, but the guard overrides it silently with a warning. This is a soft safety rail — a determined developer can remove it, but an accidental --skip-tests --env prod in a local session won't silently bypass the test suite in the most critical environment.
The saved plan file gets a timestamp suffix. Running terraform plan -out=tfplan and then terraform apply tfplan is the correct pattern — it guarantees the apply executes exactly what was reviewed. The timestamp suffix (tfplan-dev-20260228143022) prevents collisions if the script is run in parallel sessions and makes it obvious which plan file corresponds to which run. The file is deleted after apply or cancellation so stale plans don't accumulate.
The smoke test distinguishes between 401 and 403. A 401 means the Authorizer ran and rejected the request — the correct outcome. A 403 means API Gateway evaluated the Authorizer's IAM policy and denied access — the Authorizer ran but the policy construction is wrong. A 5xx means the Lambda itself crashed. The script handles each case with a distinct message pointing the operator to the right place to look.
